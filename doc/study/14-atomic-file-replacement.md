# 14. 임시 파일과 안전한 파일 교체

## 왜 필요한가
update/delete는 일부 행만 바꾸는 대신 파일 전체를 다시 쓸 수 있다. 원본 파일을 직접 덮어쓰다가 실패하면 데이터가 손상될 위험이 있다.

## 공부할 개념
- 임시 파일에 새 내용 쓰기
- 쓰기 완료 후 flush/close
- `Path.replace()` 또는 `os.replace()`
- 원자적 교체의 의미와 한계
- 임시 파일 정리와 예외 상황
- 동시 실행/동시 수정의 위험

## 미션 적용
update/delete에서 임시 파일을 작성한 후 교체하는 방식을 우선 검토한다. 구현한 보장 범위를 과장하지 않는다.

## 확인 과제
수정/삭제 전후에 정상 파일이 남는지 확인하고, 임시 파일 작성 실패 상황에서 원본이 보존되는지 테스트한다.
