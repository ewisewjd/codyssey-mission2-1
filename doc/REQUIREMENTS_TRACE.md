# Requirements Trace & 4-Pass Audit

공식 기준은 `mission_file/mission.md`, 상세 수용 기준은 `mission_file/mission_요구사항_정리.md`다. 이 문서는 문서상의 요구사항을 실제 구현 파일·테스트·실행 결과와 연결한다.

## 현재 확인 상태
- 저장소: `ewisewjd/codyssey-mission2-1`
- 확인한 트리: `README.md`, `mission_file/`, `practice_programming/`
- 애플리케이션 본체 `budget_app/`: 현재 저장소 트리에서 확인되지 않음
- 따라서 코드 근거와 실행 증거가 아직 없어 모든 기능은 미검증이다.

## 추적표 사용 규칙
각 요구사항에 대해 다음을 기록한다.
- 요구사항 ID
- 구현 파일과 함수/클래스
- 자동 테스트 또는 수동 실행 명령
- 실제 결과/증거
- 상태: 미착수 / 구현 중 / 구현 완료 / 검증 완료 / 차이 있음

## 4회 대조 절차

### 1차 — 요구사항 ↔ 구조
각 ID를 실제 코드의 파일·함수·클래스에 연결한다. 문서에만 적혀 있거나 코드가 존재하지 않으면 미완료로 둔다.

### 2차 — 정상 사용 흐름
`--help`, add, list, search, summary, budget, category, update, delete, import, export의 정상 흐름을 실행한다. 명령별 출력과 저장 결과를 기록한다.

### 3차 — 실패·경계·영속성
잘못된 날짜/타입/금액/카테고리, 없는 ID, 빈 데이터, 잘못된 CSV/JSONL, 저장 경로 오류, 재실행 후 데이터 유지, update/delete 중 원본 보존을 확인한다.

### 4차 — 회귀·최종 시연
모든 필수 명령을 다시 실행한다. README의 명령이 실제로 동작하는지, 출력 예시가 맞는지, 최소 모듈/클래스/데코레이터/타입힌트/스트리밍 조건이 코드에 있는지 재확인한다.

## 검토 기록

| 회차 | 범위 | 결과 | 실행 증거 | 수정 사항 |
|---|---|---|---|---|
| 1차 | 요구사항 ↔ 구조 | 대기 — 구현 전 | 없음 | 앱 본체 생성 후 수행 |
| 2차 | 정상 사용 흐름 | 대기 — 구현 전 | 없음 | 1차 이후 수행 |
| 3차 | 오류·경계·영속성 | 대기 — 구현 전 | 없음 | 2차 이후 수행 |
| 4차 | 회귀·평가 시연 | 대기 — 구현 전 | 없음 | 3차 이후 수행 |

실행하지 않은 항목을 통과 처리하지 않는다.
