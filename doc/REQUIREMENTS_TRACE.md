## 이번 감사에서 확인하고 수정한 항목

| 발견 사항 | 수정 방향 | 회귀 테스트 |
|---|---|---|
| `add` 입력 중 EOF/Ctrl+C가 traceback으로 노출될 수 있음 | `EOFError`와 `KeyboardInterrupt`를 사용자 메시지 및 명시적 종료 코드로 처리 | 두 중단 경로 테스트 |
| CSV export 필터 검증이 출력 파일을 연 뒤 실행되어 기존 파일을 손상할 수 있음 | 파일을 건드리기 전에 날짜·기간을 검증하고, 임시 CSV를 완성한 뒤 `os.replace`로 교체 | 잘못된 날짜/역순 기간에서 기존 파일 보존 테스트 |
| 가장 큰 거래 ID를 삭제하면 번호가 재사용될 수 있음 | `transaction_sequence.json`에 마지막 예약 번호를 보존 | 삭제한 최신 ID가 재사용되지 않는 테스트 |
| 월별 데이터가 없을 때 0원 요약을 함께 출력 | 거래가 없다는 메시지를 출력하고 일반 합계는 생략; 예산이 있으면 예산 정보만 표시 | 빈 월 요약 출력 테스트 |
| 실행 시간 메시지가 기본 화면을 어지럽힘 | 기본 출력은 조용히 유지하고 `BUDGET_APP_SHOW_TIMING=1`일 때만 데코레이터가 시간 표시 | 수동으로 기본/옵션 실행 확인 필요 |
| CSV import가 건너뛴 행의 이유를 알리지 않음 | 행 번호와 오류 사유를 반환·출력하고, 한 행이라도 건너뛰면 종료 코드 1 반환 | 부분 성공 및 전부 실패 시 이유/종료 코드 테스트 |
| 거래 금액 검증이 정수형인지 확인하지 않음 | 양수 정수만 허용 | 입력 검증 경로 포함 |

## 안전성 메모

- CSV export는 출력 대상과 같은 디렉터리에 임시 파일을 생성한다. 모든 행을 쓰고 flush/fsync한 뒤에만 `os.replace`를 호출한다. 검증 또는 쓰기 중 실패하면 기존 대상 파일을 교체하지 않고 임시 파일을 정리한다.
- 거래 ID 순번 파일은 ID를 예약할 때 갱신한다. 거래 저장이 뒤이어 실패하면 번호가 건너뛸 수 있지만, 번호를 재사용하지 않는 쪽을 선택했다.
- 기존 데이터 폴더에 순번 파일이 없으면 현재 남아 있는 거래 ID 중 최댓값부터 순번 기록을 시작한다. 이미 과거에 삭제되어 사라진 ID의 역사는 기존 데이터만으로 복구할 수 없다.
- 동시 프로세스가 동시에 ID를 예약하거나 같은 파일을 수정하는 경우의 잠금/동시성 제어는 아직 구현하지 않았다.
- `_atomic_write`는 쓰기/교체 중 예외가 발생하면 임시 파일을 정리하도록 바꿨다.

## 스트리밍 관련 판정 — 중요

- `JsonlStore.iter_transactions()`는 JSONL을 한 줄씩 `yield`한다.
- `list --limit N`은 `heapq.nlargest`로 전체 파일을 순회하며 상위 N개만 유지한다.
- `search`는 제너레이터로 필터링하지만 최신순 정렬을 위해 일치하는 결과를 메모리에 모은다.

따라서 list는 limit에 비례하는 메모리로 처리하지만, search의 최종 정렬까지 완전한 스트리밍은 아니다. 요구사항을 엄격히 해석하면 **부분 충족/개선 필요**로 기록한다. 검색의 메모리 사용을 없애면서 최신순 정렬까지 보장하려면 저장 형식 또는 조회 전략을 추가로 설계해야 한다.

## 자동 테스트 증거

이번 브랜치에서 추가한 테스트:
- 거래 ID의 삭제 후 재사용 방지
- export 날짜 검증 실패 및 역순 기간에서 기존 파일 보존
- import 행별 오류 사유 및 불완전 import 종료 코드
- add 도중 EOF/Ctrl+C 처리
- 빈 월 요약의 출력
- 기존 CSV 왕복 및 기본 기능 회귀

**주의:** 코드를 GitHub에 반영한 사실은 테스트 통과의 증거가 아니다. 이 브랜치의 GitHub Actions 결과를 확인하기 전까지 테스트 통과로 단정하지 않는다. CI 성공 후에도 테스트하지 않은 모든 입력 조합이 자동으로 검증되는 것은 아니다.
