# Requirements Trace & 4-Pass Audit

공식 기준은 `mission_file/mission.md`, 상세 수용 기준은 `mission_file/mission_요구사항_정리.md`다. 이 문서는 문서상의 요구사항을 실제 구현 파일·테스트·실행 결과와 연결한다.

## 현재 확인 상태
- 저장소: `ewisewjd/codyssey-mission2-1`
- 확인한 트리: `README.md`, `mission_file/`, `practice_programming/`
- 애플리케이션 본체 `budget_app/`: 현재 저장소 트리에서 확인되지 않음
- 따라서 코드 근거와 실행 증거가 아직 없어 모든 기능은 미검증이다.

## 추적표 사용 규칙
각 요구사항에 대해 다음을 기록한다.
- 요구사항 ID
- 구현 파일과 함수/클래스
- 자동 테스트 또는 수동 실행 명령
- 실제 결과/증거
- 상태: 미착수 / 구현 중 / 구현 완료 / 검증 완료 / 차이 있음

## 4회 대조 절차

### 1차 — 요구사항 ↔ 구조
각 ID를 실제 코드의 파일·함수·클래스에 연결한다. 문서에만 적혀 있거나 코드가 존재하지 않으면 미완료로 둔다.

### 2차 — 정상 사용 흐름
`--help`, add, list, search, summary, budget, category, update, delete, import, export의 정상 흐름을 실행한다. 명령별 출력과 저장 결과를 기록한다.

### 3차 — 실패·경계·영속성
잘못된 날짜/타입/금액/카테고리, 없는 ID, 빈 데이터, 잘못된 CSV/JSONL, 저장 경로 오류, 재실행 후 데이터 유지, update/delete 중 원본 보존을 확인한다.

### 4차 — 회귀·최종 시연
모든 필수 명령을 다시 실행한다. README의 명령이 실제로 동작하는지, 출력 예시가 맞는지, 최소 모듈/클래스/데코레이터/타입힌트/스트리밍 조건이 코드에 있는지 재확인한다.

## 문서 사전 검토 기록 — 4회 완료 (코드 검토와 별개)

| 회차 | 검토 초점 | 결과 | 확인 사항 |
|---|---|---|---|
| 문서 1차 | 공식 미션 기능 범위 ↔ 요구사항 요약 | 완료 | add/list/search/summary/budget/category/update/delete/import/export 및 3개 데이터 파일을 추적표에 반영 |
| 문서 2차 | 기술 제약 ↔ 수용 기준 | 완료 | Python 3.10+, 표준 라이브러리, CLI 도움말, 모듈/클래스/dataclass·타입힌트·데코레이터·제너레이터 반영 |
| 문서 3차 | 오류·경계·영속성 ↔ 검증 항목 | 완료 | 잘못된 입력, 없는 ID, 빈 데이터, 재실행, 손상된 파일, CSV 오류, update/delete 안전성 반영 |
| 문서 4차 | v1.5 운영 계획 ↔ study/checklist/progress/decisions | 완료 | 개념별 학습 파일, 진행 상태, 설계 결정, 최종 4회 코드 검토 절차 연결 |

## 구현 코드 대조 — 미수행

현재 저장소에 `budget_app/`가 없으므로, 위 네 회차는 문서 간 일관성 검토다. 사용자가 요청한 **구현 코드와의 4회 대조는 앱 본체가 만들어진 뒤에만 수행 가능**하다. 해당 검토는 아래 순서로 별도 기록한다.

| 회차 | 범위 | 결과 | 실행 증거 | 수정 사항 |
|---|---|---|---|---|
| 코드 1차 | 요구사항 ↔ 실제 파일/함수/클래스 | 대기 — 구현 전 | 없음 | 앱 본체 생성 후 수행 |
| 코드 2차 | 각 CLI 명령 정상 경로 | 대기 — 구현 전 | 없음 | 1차 이후 수행 |
| 코드 3차 | 오류·경계·영속성 | 대기 — 구현 전 | 없음 | 2차 이후 수행 |
| 코드 4차 | 회귀·README·평가 시연 | 대기 — 구현 전 | 없음 | 3차 이후 수행 |

실행하지 않은 항목을 통과 처리하지 않는다.
