# 04. 평가 시연 체크리스트와 알려진 제한사항

## 추천 시연 순서

1. `python3 -m budget_app --help`로 CLI를 소개한다.
2. `category list`로 기본 카테고리를 확인한다.
3. `add`로 거래 1건을 추가하고 생성 ID를 기록한다.
4. `list --limit 5`로 방금 추가한 거래를 확인한다.
5. `search --category food --type expense`로 필터 검색을 시연한다.
6. `budget set` 후 `summary --month YYYY-MM`로 사용률/초과 경고를 확인한다.
7. 거래를 수정하고 삭제해 CRUD를 시연한다.
8. `export`로 CSV를 만든 뒤 별도 테스트 CSV를 `import`해 건수를 확인한다.
9. 프로그램을 종료하고 다시 실행해 데이터가 유지되는지 확인한다.

평가 전에 실제 데이터에 영향을 주지 않도록 `--data-dir ./demo_data`를 명령어 앞에 붙여 별도 시연 폴더를 사용하는 것이 좋다.

## 테스트

```bash
python3 -m unittest discover -s tests -v
python3 -m budget_app --help
```

## 현재 확인된 제한사항

- 기본 구현에는 선택 보너스인 자동 백업과 반복 거래 생성 기능이 없다.
- CSV import는 잘못된 행을 건너뛰고 총 개수만 보고한다. 행별 오류 원인을 보여주지는 않는다.
- `list`는 `--limit`개만 유지하는 상위 항목 선택 방식으로 메모리 사용을 제한한다.
- `search`는 JSONL을 제너레이터로 필터링하지만, 최신순 결과를 정렬하기 위해 일치하는 결과를 메모리에 모은다. 따라서 검색의 최종 정렬 단계까지 완전한 상수 메모리 스트리밍은 아니다.
- 테스트 스위트 통과는 테스트한 경로가 정상이라는 증거이지, 모든 오류 상황이 검증되었다는 뜻은 아니다.
- 동시에 여러 프로세스가 같은 데이터 파일을 수정할 때의 동시성 제어는 구현하지 않았다.

## 평가 전 최종 확인

- [ ] 자동 테스트가 통과한다.
- [ ] 정상 입력과 잘못된 입력의 메시지를 직접 확인했다.
- [ ] 없는 ID의 update/delete를 확인했다.
- [ ] 사용 중 카테고리 삭제가 막히는지 확인했다.
- [ ] 데이터 폴더를 바꿔도 실행되는지 확인했다.
- [ ] CSV를 내보내고 다시 읽을 수 있는지 확인했다.
- [ ] 구현하지 않은 보너스 기능을 구현했다고 설명하지 않는다.
