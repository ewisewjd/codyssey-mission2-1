# Mission 2-1 요구사항 정리 및 검증 기준

- 공식 기준: `mission_file/mission.md`
- 참고 기준: `mission_file/mission_ 알아야할것.md`, `mission_file/STUDY_AND_IMPLEMENTATION_PLAN_v1.5.md`
- 저장 형식: JSONL
- Python: 3.10 이상
- 외부 패키지: 사용 금지(표준 라이브러리만 사용)
- 목적: 이 문서를 구현·테스트·평가 준비의 요구사항 추적표로 사용한다.
- 상태 표기: `미착수` / `구현 중` / `구현 완료` / `검증 완료` / `차이 있음`

## 1. 제품 목표

터미널에서 사용하는 영구 저장형 개인 가계부를 만든다. 단순히 정상 입력에서 실행되는 것만으로는 충분하지 않다. 잘못된 입력, 데이터가 없는 경우, 없는 ID, 재실행 후 데이터 유지, 파일 저장 중 오류까지 고려한다.

## 10. 최종 검토 4회 프로토콜

애플리케이션 초기 구현은 존재하며, GitHub Actions에서 핵심 unittest와 CLI 도움말 실행이 성공했다. 다만 이는 코드 일치 검토 4회를 완료했다는 뜻이 아니다. 아래 네 검토를 수행하고 각 증거를 기록한다.

1. **1차 — 문서 대 코드 구조:** 각 요구사항을 실제 파일·함수·클래스에 연결한다. 구현 근거가 없으면 완료로 표시하지 않는다.
2. **2차 — 명령과 정상 경로:** 모든 명령의 도움말 및 대표 정상 입력을 실행한다.
3. **3차 — 오류·경계·영속성:** 잘못된 입력, 빈 데이터, 없는 ID, 재실행 후 유지, 파일 손상/경로 오류를 점검한다.
4. **4차 — 회귀 및 평가 시연:** 전체 명령을 다시 실행하고 README·실제 출력·평가 설명이 일치하는지 확인한다.

각 검토 후 상태를 `미착수/구현 중/구현 완료/검증 완료/차이 있음` 중 하나로 갱신한다. 실행하지 않은 테스트는 통과로 기록하지 않는다.

## 11. 구현 상태 및 남은 검증

- `budget_app/`의 초기 구현을 저장소에 반영했다. 각 표의 `구현 완료`는 코드가 존재한다는 의미이며, 전체 동작 검증 완료를 뜻하지 않는다.
- GitHub Actions에서 7개 unittest와 CLI 도움말 실행이 성공했다. 실행 증거는 `doc/PROGRESS.md`와 `doc/REQUIREMENTS_TRACE.md`에 기록했다.
- list는 `heapq.nlargest`로 상위 N개만 유지한다. search는 제너레이터로 필터링하지만 최신순 정렬을 위해 결과를 메모리에 모으므로 STORE-07/TX-07은 `차이 있음`으로 기록한다.
- CSV 왕복 테스트를 추가했지만 변경 후 CI 재실행 결과 확인이 필요하다. 남은 작업은 모든 CLI 명령의 로컬 실행, 오류/경계/영속성 확인, 검색 스트리밍 설계 검토다.
